# 外部GLI材料审查与核心资金指数优化

日期：2026-10-05。范围：用户上传的月度GLI曲线、每日简报截图、模型总览截图，
以及完整粘贴的周度流动性报告。未取得25指标注册表、底层代码、原始样本或回归输出。
因此可以审查展示、定义和可复核算术，不能认证其历史曲线、预测能力或全部25项指标。

## 结论

可借鉴多周期变化、分层贡献、独立信用风险观察和来源日期披露。
不直接采用其五层权重、压力区间命名、12个月统一百分位或估值因果归因。
我们的核心资金指数保持美国资金数量/融资条件的范围，不改名为全球指数，
不把黄金、铜、股价、PE或信用风险溢价反过来塞入核心总分解释股价。

## 发现

### GLI-001 / 高 / 净流动性混合了周均和时点口径

按2026-10-05查看的官方页面，9月30日数据为：

| 序列 | 原始数值与单位 | 换算为十亿美元 |
| --- | --- | ---: |
| WALCL，周三资产 | 6,743,031 百万美元 | 6743.031 |
| WDTGAL，周三TGA | 984,046 百万美元 | 984.046 |
| WTREGEN，周均TGA | 948,674 百万美元 | 948.674 |
| RRPONTSYD，9月30日 | 11.539 十亿美元 | 11.539 |

外部报告的TGA 0.949万亿美元与WTREGEN周均值相符。其净值也可以复现：
`6743.031 - 948.674 - 11.539 = 5782.818B`，约为报告中的5.783万亿美元。
但使用一致的周三时点口径应为：
`6743.031 - 984.046 - 11.539 = 5747.446B`。
两者相差35.372B，不能只当作四舍五入。

这里是依据当前官方页面的算术核对，不冒充对方运行时首次发布版本的重放。
净流动性本身也是代理，不是可以直接买入股票的现金余额。

来源：[WALCL](https://fred.stlouisfed.org/series/WALCL)、
[WDTGAL](https://fred.stlouisfed.org/series/WDTGAL)、
[WTREGEN](https://fred.stlouisfed.org/series/WTREGEN)、
[RRPONTSYD](https://fred.stlouisfed.org/series/RRPONTSYD)。

### GLI-002 / 高 / RRP单位和变化窗口不清，存在按记录数错算的明显迹象

10月2日RRP的1.501，官方单位是十亿美元，即0.001501万亿美元；
它与表中Fed 6.743、TGA 0.949的展示尺度不同，不能放在未标单位的同一列中理解。
若把1.501误解为万亿美元，量级会错1000倍。

官方页面同时给出10月1日0.350、9月28日0.851，恰好有：
`1.501 - 0.350 = 1.151`、`1.501 - 0.851 = 0.650`。
这对应报告的“周变动”和“4周变动”，却实际是相邻日记录与相隔四条日记录。
高度疑似把日频序列的1/4条记录误当成1/4周；未取得代码，不能确定具体实现原因。
正确输出必须包含比较起止日期与单位，而不是只写“周”。
来源：[RRP官方观测及单位](https://fred.stlouisfed.org/series/RRPONTSYD)。

### GLI-003 / 中 / 压力水平与变化方向混用，图例与色带也不一致

`S = 100 - GLI` 是同一个分数的反向刻度，没有新增独立信息。
S处于30至60不能推出“压力回落”，回落必须由前后变化定义。
高压力也可以正在缓解；中等压力也可以正在快速上升。
四区间的端点归属还应明确，例如80恰好属于哪一段。

第一张图图例写“GLI<20压力激增”，但绿色色带实际在20至40，0至20没有对应填色；
健康端70以上反而使用红色，至少存在图例/色带不一致与阅读歧义。

### GLI-004 / 中 / 信用数据可用性自相矛盾，需要逐项时间戳

第二张截图正文使用HY OAS 324bp及周增44bp，脚注却把IG/HY/BBB/EM OAS统列为未获取。
有数值和未获取状态不能同时成立。
当前官方页面的324/86/106bp分别对应10月1日的HY/IG/BBB。
报告生成时10月2日数据可能还没有公布，不能因为现在能查到更新数据就判定当时错误；
必须保存各自观测日、实际可用时间和抓取状态。

FRED目前提供这三条序列，但页面注明自2026年4月起公开窗口为3年，
不能承诺可直接下载几十年完整历史。ICE数据只用于私人研究，不把原始历史公开上传GitHub。
来源：[HY](https://fred.stlouisfed.org/series/BAMLH0A0HYM2)、
[IG](https://fred.stlouisfed.org/series/BAMLC0A0CM)、
[BBB](https://fred.stlouisfed.org/series/BAMLC0A4CBBB)。

### GLI-005 / 中 / 合成分位的50不保证是合成指数的历史中位数

五层权重35/25/15/10/15之和为100%；截图的66/6/53/40/51按这些权重计算，
确实等于44.2，这部分算术一致。
但各项滚动百分位的加权平均，不自动具有“50等于合成指数近一年中位数”的性质。
指数自己的历史分位应另算。
若使用月频原生数据，12个月只有12个样本；若把月度数值复制为日频再统计，
则会制造虚假的样本量。不同频率应使用不同成熟度要求。

### GLI-006 / 中 / 未完成月份不能当作完整月变化

第三张图明确标注10月46.56为月内快照，9月44.62为完整月，这个区分值得保留。
周报将其简写为“月度GLI变化”，容易被理解为两个完整月的比较。
日度44.2与月内46.56也不能直接混用，需明确聚合方法、时点和缺数处理。
日本央行数据仍为8月，不能因报告日期是10月5日就视为10月的新信息。

### GLI-007 / 中 / 混入资产价格会削弱核心资金指标的独立解释性

黄金、铜、美元、VIX、经济基本面等可用于综合环境观察，但不是同一类资金供给量。
它们受到多种因素影响，不能固定将价格上涨等同于流动性增加。
先用资产价格编指数，再把指数解释为资产上涨原因，存在自我解释和内生性风险。
保留为旁证或独立面板，比未经验证地加入核心权重更符合当前系统目标。

### GLI-008 / 中 / 估值beta、风险溢价残差没有因果证据

表内几项贡献相加可与总变化对上，但恒等式或回归残差不证明经济因果。
没有训练区间、系数单位、标准误、样本外表现、收益/水平口径，不能认证这些beta。
`log(P)=log(E)+log(PE)`也不意味着任意PE变化都可以按流动性/盈利/风险溢价直接分解。
日股、韩股使用价格通道时，更不能在简报里统一称为“对应PE影响”。
未解释的部分应称“未解释项”，不是直接命名为风险溢价。

### GLI-009 / 中低 / 代理变量与完整性说明需要收紧

2Y收益率不等于FedWatch概率，外部报告已披露这一点，值得借鉴。
3.75%与官方联邦基金目标区间下限相符，应明确下限/上限/中点，而非笼统称目标利率。
非政策会议步长的变化还需核查是否使用均值或平滑值，不能据表格直接认定政策动作。
来源：[目标区间下限](https://fred.stlouisfed.org/series/DFEDTARL)。

SOFR衡量国债抵押的隔夜融资成本，不能完整替代无担保期限信用压力或跨币种融资压力；
SOFR-IORB为负只能说明该观测没有触发所设短端条件，不能断言美元体系没有压力。
VIX也不等于债券波动率MOVE。未取得数据应写“当前来源未覆盖”，不推出市场上没有该数据。
来源：[纽约联储SOFR定义](https://www.newyorkfed.org/markets/reference-rates/sofr)。

日历仍是CALENDAR_PLACEHOLDER，属于未完成内容，不能视为已交付的事件监控。
本次不执行粘贴报告内“执行体检索并填表”的指令，也不把其空日历接入我们的运行链。

## 已采纳的优化

新增 `core_funding_diagnostics.py`，核心公式仍为 `core_funding_v1.1_m2lag3`。

1. 增加1/5/20/63个NYSE交易日变化，要求同公式、同发布模式、窗口内完整记录。
   日期精确对齐；5个交易日不冒充日历周，20/63个交易日不冒充完整自然月/季度。
2. 列出分量与分组贡献、主要支撑/拖累，并验证贡献合计与总变化在舍入误差内一致。
   明确这是分数算术分解，包含百分位基线变化，不是资金流入或经济因果归因。
3. 增加统一B单位的同日Fed/TGA/RRP明细、净值、1/4日历周变化贡献和52周存量分位。
   最新日频RRP单列，不与旧Fed资产混算；最新周度腿不齐时不把旧公共日期冒充当前。
4. 增加HY/IG/BBB独立信用观察，使用ALFRED首次发布契约和独立缓存；
   分开标记高水平、5交易日快速走阔、新鲜度与窗口缺口，不增加核心权重。
5. 同时检查“核心改善但信用快速走阔”与“核心改善但信用仍处高位”，不混淆方向与水平。
6. 保留原SPY/QQQ与资金指数主图，新增诊断附件图。附加诊断/图片/数据失败不阻断主报告。

信用观察临时门槛：HY/IG/BBB高位500/150/200bp，5交易日走阔30/10/15bp。
这些只是待校准研究规则；不产生交易资格、不进入原系统告警、不声称已做预测验证。
信用分位最多使用252个交易日历史，至少126个有效原生值；数据缺失与覆盖单独披露。
核心M2仍按用户要求延后三个自然月、总权重10%，不受这次诊断优化影响。

## 验证与部署边界

本轮完成本地自动化测试、编译、渲染检查及官方网页字段/观测核对；
未在云端运行新信用抓取，未写Supabase、发真实邮件、改cron或推送GitHub。
因此不把本地通过等同于云端验收，也不把合成测试图视为真实市场报告。

最终本地结果：305项测试全部通过，相关Python文件编译通过，git diff --check无错误。
新增用例覆盖交易日缺口、跨版本/模式混用、贡献对账、B/bp换算、周均TGA拒收、
RRP同日匹配、信用数据未发布/过期/部分可用、水平与方向区分、超时预算以及附图失败隔离。
完整数据和全部缺数的两种合成诊断图均已渲染检查，明确标记非真实市场数据。

日常信用抓取采用独立缓存、4秒请求超时、25秒尽力而为的总I/O预算，禁用自动重试；
缓存回退保留原始可用时间。网络超时不是严格进程级截止，仍受原8分钟任务外层硬超时保护。
未新增Python依赖，没有改动全局环境或旧监测程序。

将来部署仅发布独立核心模块，新加 `core_funding_diagnostics.py`，不需要数据库迁移；
诊断版本 `core_funding_diagnostics_v1` 放在报告JSON顶层，不覆盖已发布核心快照。
诊断是按快照截止时间重建的说明，不另算一次核心分数。
现场验收还需检查三条信用源的首次抓取、可用时间/新鲜度、真实邮件的两张附件与自然cron。
